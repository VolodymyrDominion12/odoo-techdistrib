# TechDistrib — навчальний проєкт з Odoo 18

> Практичний курс: від бізнес-ідеї до робочих кастомних модулів в Odoo 18.
> Усе, що тут описано, **реально працює**: середовище підняте, код виконується,
> тести проходять.

---

## 1. Що це за проєкт

Ми будуємо ERP для вигаданої, але цілком реалістичної компанії
**«TechDistrib»** — офіційного B2B-дистриб'ютора серверного та мережевого
обладнання в Україні.

Це не «todo-list на Odoo». Ми навмисно обрали бізнес, у якому:

* багато **стандартних** процесів Odoo (закупівлі, склад, продажі, рахунки,
  серійні номери) — щоб навчитися користуватись готовим;
* є **специфіка, якої в Odoo немає** — щоб навчитися писати власну логіку;
* є місця, де стандартну поведінку треба **змінити** — щоб навчитися
  розширювати чужий код, не ламаючи його.

### Реалізовані модулі

| # | Модуль | Тип роботи | Тести | Що демонструє |
|---|--------|-----------|-------|----------------|
| 1 | `techdistrib_base` | Розширення наявної моделі | **18 ✓** | Поля в `res.partner`, `ir.sequence`, cron, view inheritance, `ir.rule` |
| 2 | `techdistrib_credit` | Нова бізнес-логіка | **24 ✓** | Блокування стандартного процесу, workflow погодження, `search=` для computed-полів |
| 3 | `techdistrib_pricing` | Конфігурація стандартного механізму | **18 ✓** | Матриця знижок → прайс-листи Odoo, синхронізація CRUD |
| 4 | `techdistrib_warranty` | Ланцюжок доказів | **21 ✓** | RMA за серійним номером, перехоплення `_action_done`, snapshot-дані |

**Разом: 81 тест, усі зелені.**

## 3. Структура проєкту

```
odoo-techdistrib/
├── README.md                  ← ти тут
├── docker-compose.yml         ← PostgreSQL 16 у контейнері
├── config/
│   └── odoo.conf              ← конфігурація сервера (детально прокоментована)
├── docs/                      ← НАВЧАЛЬНІ МАТЕРІАЛИ
├── custom_addons/             ← НАШІ модулі (те, що ми пишемо)
│   ├── techdistrib_base/
│   ├── techdistrib_credit/
│   ├── techdistrib_pricing/
│   └── techdistrib_warranty/
├── scripts/                   ← скрипти запуску й перевірки
├── data/                      ← filestore Odoo (у git не потрапляє)
└── vendor/odoo/               ← вихідний код Odoo 18 (клон, у git не потрапляє)
```

**Ключова ідея поділу:** `vendor/odoo/` — це чужий код, який ми **читаємо**,
але ніколи не редагуємо. `custom_addons/` — це наш код. Якщо ти захочеш
оновити Odoo, достатньо зробити `git pull` у `vendor/odoo`, і жодна твоя
правка не загубиться. Це головне правило розробки під Odoo.

## 4. Швидкий старт

```bash
cd /home/volodymyr/PycharmProjects/odoo-techdistrib

# 1. База даних (PostgreSQL 16 на порту 5437)
docker compose up -d

# 2. Запустити Odoo
./scripts/run_odoo.sh
```

Відкрий **http://localhost:8069**, логін `admin` / `admin`.

Якщо база ще не створена:
```bash
./scripts/init_db.sh          # створити базу techdistrib
./scripts/init_db.sh --fresh  # перестворити з нуля
```

Зупинка:
```bash
# Ctrl+C у терміналі з Odoo
docker compose down      # зупинити базу (дані збережуться)
docker compose down -v   # зупинити базу і ВИДАЛИТИ всі дані
```

## 5. Корисні команди

```bash
# Оновити модуль після зміни коду
./scripts/run_odoo.sh -u techdistrib_credit

# Встановити новий модуль
./scripts/run_odoo.sh -i techdistrib_pricing

# Інтерактивна консоль Odoo — найкращий спосіб вивчати ORM
./scripts/odoo_shell.sh -d techdistrib

# Запустити тести модуля
./scripts/run_tests.sh techdistrib_credit

# Перевірити ВСІ XML на типові помилки (не писати ж руками!)
python3 scripts/check_xml.py
```

> **Порада.** `odoo shell` — недооцінений інструмент. Замість того щоб
> щоразу тицяти в UI, перевіряй логіку одним рядком:
> ```python
> >>> env['res.partner'].search([('dealer_tier_id.code', '=', 'gold')]).mapped('name')
> ```
> Не забувай `env.cr.commit()` — інакше зміни відкочуватимуться.

## 6. Методика навчання

Не читай документи як книжку. Працюй у циклі:

1. **Прочитай** відповідний розділ у `docs/`.
2. **Знайди** згаданий файл у `custom_addons/` і прочитай код із коментарями.
3. **Зламай** його навмисно: прибери рядок, зміни значення, обери
   неправильний `comodel_name`. Подивись, яку помилку видасть Odoo.
4. **Полагодь** і поясни собі, чому саме так.
5. **Розшир** — виконай вправи в кінці уроку. Це найшвидший спосіб навчитись.

> Помилки в Odoo — твій головний вчитель. У режимі `dev=werkzeug`
> (увімкнений у `odoo.conf`) замість «Internal Server Error» ти побачиш
> повний traceback просто в браузері.

## 8. Підсумок: що ти навчився

Якщо прочитав усі уроки, ти вмієш:

**Основи Odoo**
* розрізняти модель, таблицю й подання;
* читати код ядра замість вгадування (`grep` — головний інструмент);
* запускати й читати тести, писати власні.

**Робота з наявним кодом**
* розширювати чужі моделі без їх редагування;
* перевизначати методи через `super()`, знаючи, коли що викликати;
* наслідувати подання через `xpath`, обираючи безпечні якорі.

**Власна логіка**
* будувати нові бізнес-сутності з життєвим циклом;
* блокувати стандартні процеси бізнес-правилами;
* будувати workflow погодження.

**Пастки, які вже не заскочать зненацька**
* незбережені computed-поля не можна шукати — Odoo **мовчки** ігнорує умову;
* виключення відкочує транзакцію — дані, створені перед ним, зникають;
* змішування `store=True` і `store=False` в одному обчислювачі;
* `groups=` на полі — це справжня перевірка доступу, вона ламає логіку;
* `ir.rule` обмежує рядки, ACL — операції;
* порівняння сум різних валют без конвертації;
* `@api.constrains` спрацьовує на **записі поля**, а не на виклику методу;
* порядок записів у data-файлі має значення (дії → подання → меню);
* `noupdate="1"` блокує оновлення запису — потрібен `<function>`.

   на основі моделі кредитних запитів.
4. **Погодження знижок понад ліміт** — перевикористати workflow із
   `techdistrib_credit`, не дублюючи код.
5. **Портал для дилерів** — Odoo Portal: дилер бачить свої замовлення,
   борг і статус гарантійних звернень.
